本文件记录战斗引擎推进到当前状态时的规模、覆盖范围与已知缺口，供后续接手时快速定位。规则细节以 `docs/战斗引擎_第一版.md` 为准，特性清单以该文件的 260 个小节为准。

## 三、已自动化的规则面

- **攻击**：命中/优势劣势、掩体（含生物掩体与架设工事）、视线、黑暗/云雾、天气、高差、多次攻击、重击、非致命、偷袭、附伤、武器精通 8 种、射程与触及（含长武器 10 尺）
- **防御**：AC 计算（含树肤术、护盾术、格挡、防御决斗）、抗性/免疫/易伤（模板 + 临时）、反射闪避、伤害类型统计
- **豁免与状态**：范围豁免、持续伤害、专注与专注检定、目盲/耳聋/恐慌/魅惑/麻痹/束缚/沉睡/变形/力竭/倒地/昏迷/撤离/投降
- **法术**：祝福、护盾、加速、隐形、油腻、蛛网、纠缠、雾云、黑暗、沉默、睡眠云、沉睡、定身、命令、魅惑、恐惧、致盲、耳聋、树肤、援助、群体治疗、变形、驱散魔法、法术反制、卷轴阅读与抄写、点燃油污与蛛网
- **战场**：方格移动（困难地形、泥沼、荆棘、冰面、岩浆、水下、危险格）、跳跃与坠落、拖拽被擒抱者、骑乘、灵光、掩体架设与摧毁
- **流程**：先攻（重掷、平局、手动调整、顺序调整）、准备动作（进入/离开触发、按触发距离结算）、借机攻击提示队列（上限、撤回、按类清空、一键结算、处理历史）、自动行动、回放、存档迁移

## 四、已知缺口

1. **法术覆盖**：实现了约 30 个法术，2024 规则书有 300+；高环法术、召唤与变形形态表基本未做。
2. **职业特性**：`apps/web/src/*Features.ts` 覆盖了角色卡侧的核对清单，但战斗内的职业资源（如战士的卓越骰、武僧的气）只做了通用资源池，未逐特性建模。
3. **界面验证**：沙箱内 `vite build` 因 `spawn EPERM` 无法运行，UI 层只经过 `tsc` 类型检查与纯函数测试，没有端到端点击验证。
4. **性能**：战斗档案整体 `structuredClone`（撤销栈、自动行动），超长战斗（数百回合、数十单位）未做性能测量。
5. **规则取舍**：部分细节按「可操作优先」简化，例如借机攻击不自动掷骰而是排队由操作者结算；这些取舍记录在各特性小节里。

## 五、验证方式

```powershell
# 类型检查（无输出即通过）
node node_modules\typescript\bin\tsc --noEmit -p tsconfig.json

# 全量测试（看 ℹ tests / pass / fail，整体 exit 1 属 stderr 警告噪音）
node --test --test-isolation=none "tests/*.test.cjs"
```

文档与 README 的一致性由两个护栏测试守着：`tests/docsConsistency.test.cjs`（小节编号、验证段计数）与 `tests/readmeConsistency.test.cjs`（README 声明与导出/表头/日志对照）。
