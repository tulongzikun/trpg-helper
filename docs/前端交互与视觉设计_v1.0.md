# TRPG Helper 前端交互与视觉设计规范 v1.0

> 版本：v1.0（2026-11-10）
> 对应整体产品：车卡模块 + 单机多单位战斗模块 + 角色快照导入协议
> 参考产品：TRPGCard（https://www.trpgcard.com/）公开官网与玩家文档
> 定位：**原创的前端信息架构、交互规范及视觉语言设计**，可借鉴公开设计的组织方式，不能直接复制网站前端源码、图片素材、品牌或像素级 UI
> 状态：设计文档 / 实施基线；尚非已交付的前端程序

## 1. 参考依据与明确边界

公开可观察的 TRPGCard 玩家功能包括：按规则车卡、角色卡查看、升级、装备物品、法术与资源管理。公开角色卡截图可见等级/升级入口、角色身份、六维属性，以及“概览/状态/故事/物品/法术”分栏。官网视觉采用奇幻题材、深色界面、金棕色点缀、卡片与面板分区。

参考链接：
- https://www.trpgcard.com/
- https://www.trpgcard.com/docs/player/
- https://www.trpgcard.com/docs/player/character.html （文档导航入口；部分运行环境可能无法读取）
- https://www.trpgcard.com/docs/images/player-character-sheet.png （公开玩家角色卡示例）

**我们只借鉴**：角色卡模块化信息组织、逐步车卡、角色状态集中展示、向导与预览配合、奇幻风格的轻量视觉提示。
**我们不照搬**：TRPGCard 的品牌、徽标、插画/素材、源码、精确字号尺寸和具体布局。单机战斗、召唤物、多对象 AoE、反应窗口是我们独立设计的功能。

## 2. 设计原则

1. **规则决定可点什么**：所有可用选择、动作、法术、目标、禁用原因由 domain facade 返回；UI 不自行重新写 D&D 规则。
2. **随时可理解当前状态**：角色构筑是否合法、当前单位是谁、动作/附赠动作/反应是否可用，必须在首屏可见。
3. **重要动作确认**：施法位消耗、召唤指挥、结束回合、角色发布、AoE 影响友军均应有清晰预览；避免重复弹窗造成疲劳。
4. **完整反馈链**：选择 → 检查 → 预览资源成本与影响 → 确认 → 掷骰结算 → 事件日志 → 页面局部更新。
5. **可恢复**：车卡草稿持续本地保存；战斗每次结算原子保存，刷新后恢复 PendingDecision 和战斗。
6. **上下文独立**：车卡页面无需战斗数据才能显示；战斗使用已发布快照而非实时引用草稿。
7. **优先桌面，支持平板/手机**：P0 优先 1280px 以上桌面，但所有关键操作在窄屏可用。
8. **无障碍与可解释性**：颜色不是唯一状态表达；保留键盘、屏幕阅读器和规则来源说明。

## 4. 视觉系统：奇幻氛围 + 现代专业工具效率

### 4.1 配色 / Token（建议）

| Token | 深色默认 | 浅色可选 | 用途 |
|---|---|---|---|
| bg.canvas | `#121417` | `#F7F4EB` | 页面底色 |
| bg.surface | `#1C2025` | `#FFFFFF` | 面板/卡片 |
| bg.raised | `#282D34` | `#F0ECE2` | 弹窗、选中面板 |
| border.subtle | `#363D45` | `#D8D1C4` | 分隔线 |
| text.primary | `#F5F2EB` | `#272522` | 主要文案 |
| text.muted | `#B7B2A8` | `#666156` | 次级说明 |
| accent.gold | `#D2AF70` | `#88601E` | 选中/标题/主 CTA |
| state.success | `#5BAF8A` | `#146D4C` | 可用/成功 |
| state.danger | `#E27676` | `#B23A3A` | HP 低、非法和失败 |
| state.warning | `#E9B860` | `#855600` | 消耗、友军误伤、待确认 |
| state.info | `#8BB5F2` | `#205F9C` | 法术位/资源/说明 |

深色默认可以参考 TRPGCard 的沉浸氛围，但只在品牌标题、边框和选中态使用少量金色；正文应保持高对比、信息密度与易读性。标识颜色还必须搭配文本/图标。

- 字体：正文系统无衬线（中文优先系统 CJK），大标题可以采用可商用且用户已安装的衬线字体回退；不捆绑第三方字体素材。
- 8px 基准间距：4/8/12/16/24/32；桌面面板圆角 12，弹窗 16；阴影保守。
- UI 动效：150–200ms 面板过渡；禁用持续闪烁；尊重 `prefers-reduced-motion`。
- 触控目标建议 >=44×44px；键盘可见焦点边框。

## 5. 前端布局与响应式规格

### 5.1 车卡向导：桌面 3 栏

~~~text
┌────── 顶栏：返回角色库 / 名称 / 规则包 / 自动保存状态 ─────────┐
│ [步骤栏 220–248]  [主体选择器 flex ≥620]   [实时预览 304–360] │
│ ① 规则及职业      ┌────────────────────┐  ┌─────────────┐│
│ ② 背景与物种      │ 搜索/筛选/选项卡片   │  │角色头像/名称  ││
│ ③ 属性分配        │ 规则摘要及要求       │  │等级/职业/HP  ││
│ ④ 技能与特性      │ 合法/禁用原因        │  │AC/速度/熟练  ││
│ ⑤ 装备与法术      │ 本步骤编辑交互       │  │六维/特性     ││
│ ⑥ 核对发布        └────────────────────┘  └─────────────┘│
├──────── 上一步 / 校验提示 / 下一步 / 保存草稿 ───────────────┤
└─────────────────────────────────────────────────────────────┘
~~~

- 桌面（≥1280）：三栏；中栏独立滚动，右侧实时预览 sticky；导航和工具条始终可见。
- 平板（768–1279）：左侧步骤栏折叠成水平 stepper，右侧预览变抽屉。
- 手机（<768）：单栏步骤页、底部固定导航；角色预览以可折叠的底部面板打开。
- 下步按钮只在本步骤必填有效时启用；允许暂存未完成草稿。任何失效项显示具体原因与快捷修复。
- 规则信息优先以旁侧 Info Drawer 展示，不要求离开页面查资料。

### 5.2 角色详情页

角色页采用清晰 Tab：`概览 / 能力与技能 / 特性 / 法术 / 装备 / 背景 / 修订`。
顶部固定：身份、规则版本、发布 revision、职业等级、HP 最大值、AC、速度、熟练加值，右侧「编辑」「升级」「导出」「导入战斗」。

与 TRPGCard 公开角色卡类似，六维属性卡片是一屏可扫描区块；但本项目角色卡的展示默认是**非战斗静态发布视图**，不出现战斗当前 HP 修改操作。战斗消耗只能在战斗页面执行。

### 5.3 战斗页：桌面三段式

~~~text
┌ 标题/战斗/回合/规则版/保存状态/设置 ───────────────────────────┐
│ 左：单位和先攻  │ 中：战场/行动上下文    │ 右：当前角色/结算日志 │
│ 先攻顺序        │ 格子地图 或 目标申报    │ 当前 HP/AC/状态       │
│ PC / 怪物/召唤  │ token(颜色表示阵营)   │ Action □ Bonus □      │
│ 召唤归属树      │ 范围模板和覆盖预览      │ Reaction □ Move 30ft  │
│ HP/状态微卡     │ “选择下一步操作”CTA    │ 技能/法术快捷入口      │
│                 │                      │ 可折叠结算日志        │
└──────────────────────────────────────────────────────────────┘
~~~ 

移动端折叠先攻侧栏，战场占主区；单位信息以底部 Sheet，日志以单独 Tab。无地图模式不得虚构距离和掩护验证，应明显显示“目标范围由操作者确认”。

## 6. 车卡向导分步交互规范

| 步骤 | 核心控件 | 实时反馈 | 合法性条件 |
|---|---|---|---|
| 规则/职业 | 单选卡 + 来源筛选 | 命中骰、职业特性、可选择技能数 | 规则版/职业存在 |
| 背景/物种 | 带搜索的图文选项卡 | 熟练、语言、起源专长和移动 | 背景加点来源正确 |
| 六维属性 | 标准数组拖拽 / 点购计数 / 掷骰记录 | modifier / HP / 技能 / DC 实时刷新 | 点购不超 27，合法分配 |
| 技能/特性 | 多选列表、必选计数、前置条件标签 | “还需选择 N 项” | 选择数与互斥约束通过 |
| 法术/装备 | 可搜索目录、详情侧栏、过滤器 | 法术位、攻击、AC、负重（如启用） | 合法的来源/准备/装备 |
| 核对发布 | 错误列表、角色卡全览、来源追踪 | ERROR/WARN/INFO 汇总 | ERROR 清零才能发布 |

交互要点：

- 向导步骤可以来回跳，改职业时提示：“有 3 个后续选择将重新校验”，一键打开受影响清单。
- 条目禁用时不是消失：显示🔒及具体条件（等级不足、已选满、缺少熟练等），如选择过多则解释限额。
- 法术和特性采用「搜索 + 分类 + 详情抽屉 + 选择」流程，避免长篇说明阻塞操作。
- 能力与装备造成的静态数值变化显示“由 14 → 16，来源：背景 +2”，并保留计算解释。
- 完成后显示“已发布 Revision N（不可变）”，可在角色库立即点击“导入战斗”。

## 7. 战斗操作：统一“选择操作”弹窗（P0）

### 7.1 弹窗结构（每次实际行动必经）

~~~text
┌────────────────── 发起战斗行动 ───────────────────────────────┐
│ 第 3 回合 / 战士 F1 的回合                                      │
│ 步骤 1 操作者 ─ 步骤 2 行动 ─ 步骤 3 目标/区域 ─ 步骤 4 预览确认  │
│                                                              │
│ [F1 战士] 当前轮到；[S1 野兽伙伴] 需指挥；[W1 法师] 不可操作     │
│                                                              │
│ 普通动作 ●可用  附赠动作 ●可用  反应 ○已消耗  移动 25/30 ft      │
│                                                              │
│ [攻击] [施法] [使用特性] [移动] [物品] [结束回合]                │
│ 列表：可用技能 + 资源消耗 + 时机限制 + 无法使用原因              │
│                                                              │
│ [返回]                          [预览结果] [确认行动]         │
└──────────────────────────────────────────────────────────────┘
~~~

- 第一步始终明确当前操作单位（包含受控召唤物），但普通回合不得让任意非轮到者越过先攻规则。
- 单击单位后取得 `getLegalActions(actorId, decisionWindow)`。只由引擎判定合法性。
- 无可用附赠动作时，显示禁用“附赠动作已使用（本回合 1/1）”；无法因为动作如潮再打开。
- 5 级战士的 Extra Attack 在一次 Attack action 中展示 `攻击 1/2`、`攻击 2/2`；再次用 Action Surge 产生额外普通动作的第二个攻击序列。不能把连打误显示成两个附赠动作。
- 召唤指挥必须展示由谁支付行动成本，例如“主人 F1：消耗附赠动作”；若主人已使用附赠动作则禁用指挥并给原因。
- 点击取消不能消费资源或掷骰；成功提交后即时落库，重复点击/刷新不得重复结算（commandId 幂等）。

### 7.2 行动确认前后

确认前呈现：攻击命中加值/法术 DC、距离/射程校验状态、行动成本、法术位/职业资源、可能受到影响的对象、骰子计算方式及需要手动确认的规则。

确认后页面先显示事件进度，再显示结算结果（各骰子、加值、豁免、伤害/抗性/临时 HP 扣减、专注、死亡），如有合法反应须先暂停弹出反应窗口再继续。

反应窗口必须显示：触发事件、可响应者（含合法召唤物）、可使用反应、资源消耗、放弃选项；挂起时禁止开始另一项正常动作。

## 8. AoE 范围交互（包含所有 PC、怪物、召唤物）

### 8.1 地图模式

1. 玩家选择法术/能力；
2. 前端显示球/锥/线/立方体模板和合法施法起点，拖动调整范围；
3. 调用 `previewTargets()` 获取**所有**覆盖对象（所有阵营的 PC、怪物、召唤物，符合规则的其他生物）；逐个列出候选列表；
4. UI 标注“友军 X / 敌方 Y / 召唤物 Z”，友军影响使用警示，但不会因此默认剔除；
5. 对规则规定的**区域自动影响**目标，列表只允许查看/确认，不允许自行勾除；对规则明确允许“自选 N 个目标”或排除者，才提供可勾选开关；
6. 用户确认后才向引擎提交范围参数，而不是传一个随意过滤后的目标 ID 列表；
7. 系统对每个合法目标分别掷豁免、修正抗性/免疫、应用伤害/状态，生成逐目标日志；同一 AoE 的伤害骰是否共用由具体规则决定；
8. 一次效果内的专注失效与召唤物消失要按事件顺序安全处理，不能边遍历可变集合边丢目标。

### 8.2 无地图目标申报模式

显示黄色说明：“无地图：系统无法自动判定墙壁、距离和精确范围，请手动申报覆盖对象。”操作者可以从包括友军和召唤物在内的完整单位列表选择受影响者，并记录手动裁定标记，不伪装为严格地图计算。

### 8.3 AoE 预览卡片示例

| 对象 | 所属 | 类别 | 覆盖 | 结算 |
|---|---|---|---|---|
| W1 法师 | 蓝方 | PC | 范围外 | 无 |
| F1 战士 | 蓝方 | PC | 范围内 | DEX 豁免 + 伤害 |
| S1 火元素 | 蓝方 | 召唤物 | 范围内 | DEX 豁免 + 火免疫校验 |
| O1 兽人 | 红方 | 怪物 | 范围内 | DEX 豁免 + 伤害 |
| S2 幽影 | 红方 | 召唤物 | 范围内 | DEX 豁免 + 伤害 |

上表仅作 UI 数据示例；实际结果、能否豁免和伤害类型由当前规则包定义。

## 9. 召唤单位的可见性和控制体验

先攻列表需清晰显示父子关系，例如：

~~~text
F1 战士 Lv5            HP 32/44
  └─ S1 野兽伙伴      HP 12/20    受 F1 指挥
W1 法师 Lv5            HP 19/30
  └─ S2 元素生物      HP 24/30    专注：召唤元素
O1 兽人                HP 10/15
~~~

- 单位头像角标表明 PC/怪物/召唤物类型；召唤物同时属于具体阵营并拥有独立目标选择能力。
- 召唤物列表显示主人、召唤来源、独立/跟随/共享回合类型、指挥成本、专注关联、剩余时长。
- 点击召唤物打开详细侧栏，列出本单位的行动预算和不可用原因，不允许把主人剩余附赠动作错误显示为召唤物额度。
- 召唤物消失时显示原因（主人专注失败、持续时间耗尽、HP=0 等）并从先攻/地图移除，同时保留事件日志和历史引用。
- 普通怪物的 Multiattack 在行动弹窗中作为一个动作，内含多段子攻击；各子攻击可分别选目标。

## 10. 车卡导入战斗弹窗

~~~text
┌──────────── 导入角色到战斗 ─────────────────────────────┐
│ 选择已发布角色（支持多选）                                 │
│ [✓] 战士 F1 Lv5 · 2024 · Rev 3                          │
│ [✓] 法师 W1 Lv5 · 2024 · Rev 2                          │
│ [ ] 游荡者 R1 Lv3 · 2014 · 不兼容（显示原因）              │
│                                                           │
│ 当前战斗：2024 / srd-5.2.1 · hash: …                       │
│ 阵营：[蓝方 ▼]  初始 HP：[满血 ▼] 资源：[全部恢复 ▼]          │
│ 导入检查：2 可导入 / 1 不兼容                              │
│ [取消]                                     [确认导入 2]      │
└───────────────────────────────────────────────────────────┘
~~~

- 只列发布快照；草稿显示“发布后可导入”，不能被错误计入可导入数。
- 自动检查规则包版号/hash、缺失特性定义、装备引用、职业能力映射，失败可展开具体原因。
- 确认导入后每个角色获得**新的 BattleActor ID**，当前 HP、法术位等只初始化到战斗存档，不影响原车卡。
- “正在进行的战斗”不自动响应角色卡升级；支持查看来源 Revision 和原快照。
- 保存/恢复双模块数据独立；角色库只存 character drafts / published snapshots，战斗库存 battle snapshot / log。

## 12. 设计组件库与实现技术建议

- React + TypeScript + Vite；**不要求 SSR 或服务端**。
- 样式：Tailwind CSS + CSS Variables（独立主题令牌），交互基础组件可选择 Radix UI（Dialog、Popover、Tabs、Tooltip）以获得可访问性/焦点管理。
- 状态：UI 临时状态在组件内；车卡草稿和战斗快照分别放入独立 feature state；领域真相来自 `character-core`、`combat-core`，不复制第二套计算规则。
- 数据验证：Zod / JSON Schema 用于表单与导入格式；本地持久化：IndexedDB（Dexie 可选）。
- 表单：React Hook Form 只负责输入/交互状态；职业和法术合法性来源于 Choice Engine，不依赖表单控件本身判断。
- 组件演示：Storybook（可选但推荐）为角色属性卡、资源条、行动弹窗、AoE 预览等建立单独示例。
- 路由建议沿用《车卡系统_独立模块设计_v1.0.md》，详见《系统总体架构_v3.0.md》。

接口示例：

~~~typescript
type ActionOptionVM = {
  abilityId: string;
  title: string;
  actionCost: "ACTION" | "BONUS_ACTION" | "REACTION" | "NONE";
  enabled: boolean;
  disabledReason?: string;
  resourceCostLabel?: string;
  targetMode: "SELF" | "SINGLE" | "AREA" | "SPECIAL";
};

type TargetPreviewVM = {
  shapeLabel: string;
~~~

示例 ViewModel 表示 UI 输入，不代替实际规则判定及契约定义；界面组件不能修改 `bonusActionUsed` 或伪造 `included` 来跳过裁决。

## 13. 禁用与异常状态设计

必须覆盖：

- 规则未安装；角色来源版本不一致；装备/法术无定义；车卡未完成；上游选择失效；草稿自动保存失败；
- 无目标/越距/被掩护阻挡（地图模式）或距离未知（声明模式）；
- 当前回合无普通动作；附赠动作已经 1/1；反应在下个自身回合前不可恢复；法术位/职业资源不足；
- 当前有悬而未决的反应窗口，禁止执行下一动作；
- 召唤主人失能、无法指挥、专注中断或召唤物已消失；
- AoE 包含友军/召唤物警告；技能不允许自由排除覆盖者；
- 战斗结算异常时保留之前状态并展示可重试/手动裁定/导出诊断信息。

错误呈现需分为 `blocking / warning / informational`，屏幕阅读器可读，避免只用红色提示。

## 14. 前端状态机与数据边界

~~~text
车卡：LIBRARY → EDIT_DRAFT → VALIDATE → PUBLISH → SHEET
                     ↑        │
                     └─ ERROR ┘

战斗：SETUP → ACTIVE → ACTION_DIALOG → PREVIEW
                     ↑                    │
                     │                    ▼
                     └──── RESOLVED ← REACTION_WINDOW
                                      │
                                      └─ 等待响应 / 放弃
~~~

车卡弹窗属于独立 UI 上下文，不得重用战斗的 PendingDecision / 资源消费状态；战斗决策状态必须可序列化，并在页面刷新后重建。

典型命令处理：

~~~typescript
async function onConfirmAction(cmd: BattleCommand) {
  const result = battleEngine.submit(cmd); // 领域层唯一裁决
  if (!result.ok) return showValidationIssues(result.error);
  await battleRepository.saveAtomically(result.nextState, result.events);
  renderFromBattleState(result.nextState);
}
~~~

`battleEngine.submit` 可以产生 WAITING_DECISION 而不直接结束全部伤害结算。不可在 UI 中预先扣 HP、先支付附赠动作或先移除召唤物，否则取消和反应会破坏一致性。

## 15. 前端验收与自动化测试

### 15.1 车卡（UI + 领域一致性）

- [ ] PC 可以在不打开任何战斗页时完成创建、自动保存、升级、发布和导出。
- [ ] 职业/背景/物种改变后，高亮受影响选择并标出禁用原因。
- [ ] 非法六维分配、未完成选择不能发布；刷新后草稿仍可恢复。
- [ ] 已发布角色卡的 HP 是最大值，不误显示战斗当前 HP。
- [ ] 角色库导入战斗弹窗显示 schema 版、RulePack 兼容检查和来源修订号。

### 15.2 战斗（UI + 引擎一致性）

- [ ] 所有 PC/怪物/召唤物都出现在先攻或合法受控单位列表；不因类型遗漏召唤物。
- [ ] 普通回合操作窗口不能选非当前合法单位；反应窗口只允许有合法反应的单位。
- [ ] 战士 5 级一次 Attack 动作显示 2 次攻击机会；Action Surge 再次允许普通动作，附赠动作仍只能 1 次。
- [ ] 消耗 Second Wind 后，另一个 Bonus Action 按钮变禁用并标出 1/1。
- [ ] 召唤指挥正确显示主人支付额度、前置条件和禁用原因。
- [ ] Fireball 范围预览完整列出 PC、怪物和召唤物，自动覆盖型技能不允许“自行取消目标”。
- [ ] AoE 逐对象的豁免、伤害、抗性、死亡/消失在日志分别显示。
- [ ] 有合法 Shield 等反应时，先暂停并弹出响应窗口再最终扣伤害。
- [ ] 页面重载后能恢复 PendingDecision，取消动作不丢失状态、不重复消费资源。
- [ ] 无地图模式显示人工覆盖确认标记，不冒充自动精确几何裁决。

### 15.3 工程质量验收

- 可用键盘走完车卡、操作弹窗、法术/目标选择、确认和取消；Esc 与焦点管理符合模态规范。
- Chrome/Edge/Firefox 核心功能可用；响应式目标宽度 375、768、1280、1600px。
- 字体缩放到 200% 后主操作可见；低视力用户仍能区分行动资源可用/禁用。
- 高密度数据采用虚拟列表/分页；角色库 100 张卡、怪物库 1000 条目仍可搜索和过滤。
- 自动化截图基线：角色库、车卡选择、属性分配、角色详情、战斗主界面、AoE 弹窗、反应弹窗、角色导入弹窗，各至少一个固定测试态。
