# 战斗引擎（先攻、回合与扩展规则）

> 状态：2026-11-17，v2.32，本地实现，无新依赖。
> 目标：让战斗从“准备阶段”进入可运行的回合制，先覆盖最常用的一条完整链路，再逐步扩展多重攻击、AoE、持续效果、召唤物、攻击来源、方格战场、掩体、借机攻击、困难地形、墙体视线、撤离与职业特性。

## 1. 本轮范围

已在 `apps/web/src/combat.ts` 实现纯函数引擎，并在 `CombatViews.tsx` 接入战斗页：

- **先攻**：自动投 d20 + 先攻加值，可手工覆盖；平手依次比较敏捷调整值与名称。角色先攻会纳入敏捷、警觉专长（背景或人类起源专长）与幽影潜行者（ gloom stalker ）的感知加值；勇士与刺客在 3 级起显示先攻优势并自动取高值。
- **回合**：记录轮次、当前单位、先攻顺序；结束回合时跳过已死亡单位，轮末进入下一轮，并重置动作、附赠动作、反应与移动。
- **动作经济**：动作、附赠动作、反应分别限一次（反应可在非自己回合使用）；移动按速度累计，超出上限会拒绝。
- **攻击**：d20 + 攻击加值对抗 AC，支持正常／优势／劣势、大失败必失、自然 20 必中、重击范围（默认 20，可传入 15–20）。
- **伤害**：解析 `NdM±K` 伤害骰，重击翻倍骰数但调整值只加一次；按目标的抗性／易伤／免疫结算，先扣临时生命再扣当前生命。
- **倒地与死亡**：角色生命值归零进入倒地并可投死亡豁免（10 成功、1 记两次失败、20 恢复 1 点、3 次失败死亡）；怪物归零直接死亡；过量伤害达到最大生命值时角色立即死亡。
- **其他**：状态标记、临时生命、战斗日志（含掷骰明细）、最多 20 步撤销、重置战斗；战斗数据写入原有 `trpg-helper.battles.v1` 存档。

## 2. 数据与兼容

`Battle` 与 `Actor` 新增可选字段，旧存档不需要迁移：

```ts
type CombatantState = {
  initiative: number; tempHp: number; conditions: string[];
  actionUsed: boolean; bonusUsed: boolean; reactionUsed: boolean;
  movementUsed: number; status: 'active' | 'down' | 'dead';
  deathSaves: { successes: number; failures: number };
};
type CombatState = {
  round: number; turnIndex: number; order: string[];
  log: { id: string; round: number; text: string; detail?: string }[];
  undo: Battle[]; // 最多 20 份快照，快照内 undo 清空
};
```

- 存档仍为 `version: 1`；`readBattles` 会校验新增字段，损坏数据不会被覆盖。
- 开始战斗后拒绝再向该战斗添加单位；需要先点“重置战斗”。
- 移除单位会同步先攻顺序并修正当前回合索引。

## 3. 接口一览

|---|---|
| `startCombat(battle, initiatives?, deps?)` | 投先攻、建立顺序、进入第 1 轮 |
| `endTurn(battle)` | 推进到下一个存活单位 |
| `attack(battle, options, deps?)` | 完整攻击结算，返回 `{ battle, outcome }` |
| `attackSequence(battle, options, deps?)` | 一次攻击动作内连续攻击（额外攻击），返回 `{ battle, outcomes }` |
| `useActionSurge(battle, actorId, deps?)` | 战士动作如潮：消耗一次使用次数并重置动作 |
| `secondWind(battle, actorId, deps?)` | 战士回气：附赠动作恢复 1d10 + 战士等级 |
| `recoverClassResources(battle, deps?)` | 短休：恢复动作／附赠动作／反应／移动与职业资源次数 |
| `savingThrow(battle, options, deps?)` | 单个单位掷豁免并写入日志，返回 `{ battle, outcome }` |
| `areaSave(battle, options, deps?)` | 范围效果：逐目标豁免、伤害减半与抗性结算，返回 `{ battle, results }` |
| `addOngoingEffect` / `removeOngoingEffect` | 挂上或移除回合开始的持续伤害 |
| `startConcentration` / `endConcentration` | 开始或结束专注；受伤时自动检定 |
| `tickTurnStart(battle, deps?)` | 结算当前单位的持续效果（`endTurn` 会自动调用） |
| `markSummon` / `dismissSummon` | 把已有单位标记为某个专注法术的召唤物，或解除标记 |
| `syncSummons(battle, deps?)` | 清理施法者已无法维持的召唤物（`endTurn` 会自动调用） |
| `summonsOf(battle, ownerId)` | 列出某个施法者当前的召唤物 |
| `attackSources(actor)` | 列出可用的攻击来源（怪物动作、角色文本、装备武器、估算） |
| `parseAttackText(text)` | 从中文攻击描述解析加值、伤害骰、类型与射程 |

| `cellDistance(from, to)` / `actorDistance(battle, a, b)` | 按 Chebyshev 距离换算格数与尺数（斜向算一格） |
| `positionOf(battle, actorId)` | 读取单位所在格子 |
| `actorReach(actor)` | 单位的近战触及范围（取攻击来源中最远的近战距离，至少 5 尺） |
| `pendingOpportunities(battle)` | 当前待结算的借机攻击提示 |
| `opportunityAttack(battle, reactorId, overrides?, deps?)` | 用反应结算借机攻击并移除提示，返回 `{ battle, outcome }` |
| `declineOpportunity(battle, reactorId, deps?)` | 放弃借机攻击并移除提示 |
| `toggleDifficultCell(battle, x, y, deps?)` | 切换某格的困难地形标记 |
| `difficultCells(battle)` / `isDifficultCell(battle, x, y)` | 读取困难地形格子／判断单格 |
| `toggleWallCell(battle, x, y, deps?)` | 切换某格的墙体标记 |
| `wallCells(battle)` / `isWallCell(battle, x, y)` | 读取墙体格子／判断单格 |
| `hasLineOfSight(battle, from, to)` | 两格之间是否有未被墙体阻挡的直线视线 |
| `disengage(battle, actorId, deps?)` | 撤离：消耗动作，本回合移动不引发借机攻击 |
| `suggestAttacks(battle, actorId, limit?)` | 列出当前可执行的攻击建议（目标、来源、距离、原因、评分） |
| `hasImmediateAttack(battle, actorId)` | 是否已有无需移动即可执行的攻击 |
| `coverFromWalls(battle, from, to)` | 按墙体遮挡推算掩体等级（无／半掩体／四分之三掩体） |
| `readyAction(battle, actorId, { action, trigger }, deps?)` | 准备动作：以动作为代价预置反应 |
| `triggerReadyAction(battle, actorId, deps?)` | 触发准备好的动作，消耗反应 |
| `cancelReadyAction(battle, actorId, deps?)` | 放弃准备好的动作（不返还动作） |
| `offhandAttack(battle, options, deps?)` | 附赠动作副手攻击（轻型武器；双武器战斗风格保留属性加值） |
| `grapple` / `shove(battle, { attackerId, targetId }, deps?)` | 擒抱或推撞（推倒／推开 5 尺），力量（运动）对抗 |
| `escapeGrapple(battle, actorId, deps?)` | 挣脱擒抱：DC = 8 + 擒抱者力量调整值 + 熟练加值 |
| `autoAct` / `autoTurn` / `autoSide` | 自动行动（攻击／移动／待命）、自动回合、指定阵营整轮自动 |
| `applyFallDamage(battle, actorId, feet, deps?)` / `jumpDistance(actor, kind, runningStart?)` | 坠落伤害（每 10 尺 1d6，封顶 20d6）与跳远／跳高距离 |
| `castSpell(battle, options, deps?)` | 施放法术：消耗动作／附赠动作，按攻击或豁免结算，可挂专注 |
| `settleBattle(battle)` / `settlementText(battle)` | 战斗结算摘要（经验、每单位 HP／状态／资源）与可复制文本 |
| `addReinforcement(battle, card, input, deps?)` | 战斗中加入增援并按先攻插入顺序 |
| `addAura(battle, input, deps?)` / `removeAura(battle, auraId, deps?)` | 添加或结束灵光（半径内同阵营单位获得 AC／豁免加值） |
| `reloadAmmo(battle, actorId, count?, deps?)` | 补充弹药（带「弹药」特性的武器每次攻击消耗 1 发） |
| `activeAuras(battle, actorId)` / `auraBonus(battle, actorId, kind)` | 读取影响某单位的灵光与被动的加值合计 |
| `standUp(battle, actorId, deps?)` | 起身：消耗一半移动力并移除「倒地」标记 |
| `damageActor` / `healActor` / `setActorHp` / `setTempHp` | 生命值类操作 |
| `spendResource` / `spendMovement` | 动作经济与移动 |
| `toggleCondition` | 添加或移除状态 |
| `rollDeathSave` | 死亡豁免 |
| `undoCombat` / `resetCombat` | 撤销与重置 |

`deps` 可注入 `random`（0–1 均匀分布）、`makeId`，测试用固定骰子流重放。

## 4. 条件修正、多次攻击与职业行动（v1.1）

`apps/web/src/combatModifiers.ts` 集中处理状态对攻击的影响，`attack`／`attackSequence` 自动应用，界面只需选择近战或远程、距离与攻击次数。

- **攻击者侧**：隐形 → 优势；目盲、中毒、恐慌、束缚、擒抱（目标非擒抱者）→ 劣势。
- **目标侧**：麻痹、昏迷、石化、束缚、目盲 → 攻击者优势；倒地 → 近战优势、远程劣势；隐形 → 攻击者劣势。
- 优势与劣势同时存在时按规则互相抵消为正常检定；手工选择的检定方式与状态修正合并计算，日志会列出全部来源。
- **自动重击**：对麻痹或昏迷的目标、在 5 尺内用近战攻击命中即重击，伤害骰翻倍。
- **无法行动**：失能、麻痹、昏迷、石化、死亡、倒地会统一拦截 `spendResource`、`spendMovement`、`attack`、`useActionSurge`、`secondWind`。
- **多次攻击**：`attacksPerAction` 按职业与等级给出上限——战士 5／11／20 级为 2／3／4 次，野蛮人、武僧、圣武士、游侠 5 级起 2 次，英勇学院吟游诗人 6 级起 2 次。`attackSequence` 一次只消耗一个动作，目标死亡后提前结束并记录每次攻击明细。
- **动作如潮**：战士 2 级 1 次、17 级 2 次，使用后重置本回合动作；**回气**：附赠动作恢复 1d10 + 战士等级，二者均在短休（`recoverClassResources`）或长休后恢复。
- 存档新增两个可选字段 `actionSurgeUsed`（0–2）与 `secondWindUsed`，仍为 `version: 1`，旧存档可直接读取。

## 5. 豁免与范围效果（v1.2）

- `savingThrow(battle, { actorId, ability, dc, bonus?, mode? })`：掷 d20 + 加值，天然 20 必定成功、天然 1 必定失败；结果与全部修正来源写入战斗日志。
- **自动失败**：处于麻痹、昏迷或石化的单位，力量与敏捷豁免直接失败（不掷骰）；**束缚**使敏捷豁免处于劣势。手工指定的优劣势与状态修正合并，冲突时互相抵消。
- `areaSave(battle, { targetIds, ability, dc, damageExpression, damageType, halfOnSuccess?, bonuses?, mode? })`：一次伤害骰对所有目标生效，每个目标单独掷豁免；成功时伤害减半（`halfOnSuccess: false` 可改为成功免伤），失败承受全额；抗性、免疫、易伤与临时生命照常结算。重复目标自动去重、死亡目标跳过，一次最多 20 个目标。
- 界面：`TurnPanel` 新增「豁免与范围效果」卡片——勾选目标（默认全选存活单位），选择豁免属性、DC、加值、伤害骰与伤害类型，可关掉成功减半；「单体豁免」只掷骰写日志，「结算范围伤害」逐目标结算。

## 6. 持续效果与专注（v1.3）

- `addOngoingEffect(battle, targetId, { name, damageExpression, damageType, saveEnds? }, deps?)`：给单位挂持续伤害；每个单位最多 8 个。
- `removeOngoingEffect(battle, targetId, effectId, deps?)`：手动结束持续效果。
- `tickTurnStart(battle, deps?)`：结算当前单位的持续效果。`endTurn` 推进回合后会自动调用，也可单独调用。
- 结算顺序：先掷「豁免结束」的豁免（成功则移除且不受伤），否则掷伤害骰并结算抗性、临时生命；因此被灼烧的目标可能在回合开始时倒地。
- `startConcentration(battle, actorId, spell, deps?)` / `endConcentration(battle, actorId, deps?)`：开始或结束专注，开始新专注会替换旧的并记录日志。
- **专注检定**：受到伤害时自动掷体质豁免，DC = max(10, 伤害 ÷ 2)；失败或倒地／死亡立即失去专注。攻击、范围伤害、手动伤害与持续伤害四条路径都会触发。
- 默认豁免加值：`defaultSaveBonus(actor, ability)` = 属性调整值 + 角色快照里已熟练的豁免（怪物按模板属性）；未显式传 `bonus` 时自动使用。
- 界面：`TurnPanel` 新增「持续效果与专注」卡片——显示专注与持续效果标签（可点 × 移除）、开始专注、以及添加持续效果（名称／伤害骰／类型／可选的回合开始豁免）。

## 7. 战斗档案与战报（v1.4）

- `exportBattle(battle, now?)`：导出为 JSON 文本，外层带 `schema: 'trpg-helper.battle-export/v1'` 与 `exportedAt`；撤销历史（`undo`）不会写进档案。
- `importBattle(text, takenIds?)`：接受带外层的档案，也接受裸战斗对象；与本地已有 id 冲突时自动加 `-2`、`-3` 后缀，不会覆盖原战斗。
- `battleTranscript(battle)`：生成 Markdown 战报——参战单位（AC、生命值、状态、专注与持续效果）、按轮次分组的战斗日志。
- 导入前的校验复用 `validateBattle(value)`：结构不符时抛出「战斗数据格式无效，无法导入。」，JSON 解析失败与版本不符也各有中文提示。
- 界面：战斗页底部新增「导入 / 导出战斗」折叠卡片——导出文本可下载 JSON 或复制、「生成战报」输出 Markdown；粘贴档案后点「导入战斗」会把新战斗加入列表并切换过去。

## 8. 召唤物与专注（v1.5）

- `markSummon(battle, actorId, { ownerId, spell?, rounds? }, deps?)`：把场上已有单位标记为施法者的召唤物，绑定来源法术与可选的持续轮数。不新建合成单位，避免伪造 `source.entryId`／`blockId`；`spell` 缺省取施法者当前专注的法术。
- 限制：只有正在维持专注且未死亡的单位可以拥有召唤物；单位不能把自己标记为自己的召唤物；持续轮数须为 1–99 的整数。
- **消散时机**：施法者失去专注（专注检定失败、倒地或死亡、主动结束专注、改用其他法术专注）时，其召唤物立即消散；消散会写入日志并把单位移出战斗，先攻顺序与当前回合索引同步修正。
- **持续轮数**：每轮到施法者回合开始时递减，归零即消散；留空表示不限时长。
- `dismissSummon(battle, actorId, deps?)` 只解除绑定、保留单位（召唤被打断但生物仍在场的场合）。
- `syncSummons` 与内部 `tickSummonDurations` 由 `endTurn` 自动调用；`summonsOf(battle, ownerId)` 供界面列出。
- 存档：`Actor.summon = { ownerId: string; spell: string; rounds?: number }` 为可选字段，`isActor` 校验，旧存档无需迁移，仍为 `version: 1`。
- 界面：`TurnPanel` 新增「召唤物」卡片——列出召唤物（名称、来源法术、剩余轮数，可点 × 解除）；选择要标记的单位与持续轮数后提交；没有专注时提示先开始专注。单位卡显示「召唤物」徽章与来源法术。

## 9. 攻击来源的结构化解析（v1.6）

- `apps/web/src/attackSources.ts` 把攻击加值与伤害骰从「按属性估算」升级为结构化来源，攻击面板的「攻击来源」下拉可切换，选中后自动填入加值、伤害骰、伤害类型、远近与距离，仍可手改。
- `parseAttackText(text)`：识别中文攻击描述中的 `+X 命中`、`N (2d6+3) 火焰伤害`、`触及 N 尺`、`射程 N/N 尺`，也接受不带括号的伤害骰写法。
- `monsterAttackSources(actor)`：遍历怪物卡 `actions`，能解析出加值与伤害骰的动作各成一条来源；「多重攻击」这类纯说明会被跳过。
- `characterWeaponSources(actor)`：从角色 `details.equipment` 里按常用武器表（长剑、短剑、匕首、刺剑、巨剑、巨斧、战锤、长棍、长矛、戟、长弓、短弓、轻弩、手弩、投石索、标枪）匹配，命中加值 = 属性调整值 + 熟练加值，伤害 = 武器骰 + 属性调整值。武器精通与熟练项未建模，按已熟练处理。
- `characterTextSources(actor)`：解析角色「攻击与法术」文本中每行「名称：+X 命中……」的自定义攻击（如法术攻击）。
- `attackSources(actor)`：优先级为角色文本 → 装备武器（角色），或怪物动作（怪物）；都没有时回落到按最佳属性估算，并在下拉中标注来源。
- 未实现：武器熟练／专长（巨武器战斗等）对伤害的重掷与加值、弹药与装填、武器特性（灵巧已按最佳属性近似处理）。

## 10. 方格战场与距离校验（v1.7）

- `configureGrid(battle, { width, height, cellFt })`：启用方格（宽高 1–60 格、每格 5–30 尺）；传 `null` 关闭并清除所有单位位置。缩小方格时越界单位的位置自动清空。
- `moveActorToCell(battle, actorId, x, y)`：未放置的单位可以直接放到空位（战斗开始后也可以）；已放置的单位在战斗中移动需要轮到它，并按 `格数 × cellFt` 扣减移动力，超出速度上限会被拒绝。目标格已有单位、坐标越界或非整数都会报错。
- **距离**：`cellDistance` 用 Chebyshev 距离（斜向算一格），`actorDistance` 换算成尺。双方都已放置时，攻击自动使用方格距离：近战超过 `reachFt`（默认 5，可由攻击来源给出，如戟 10 尺）会被拒绝，远程超过 600 尺会被拒绝；日志会写「方格距离 N 尺」。
- 未放置的单位仍按攻击面板手工填写的距离结算，方格是可选增强，不影响已有战斗。
- 存档：`Battle.grid?: { width, height, cellFt }` 与 `Actor.position?: { x, y }` 均为可选字段，`isGrid`／`isPosition` 校验，旧存档无需迁移，仍为 `version: 1`。
- 界面：战斗页新增「方格战场」面板——未启用时填写宽高启用；启用后点格子选择／放置单位、显示未放置单位、列出当前行动者与各单位的距离，可一键关闭方格。

## 11. 掩体（v1.8）

- `AttackOptions.cover?: CoverType`（`'无' | '半掩体' | '四分之三掩体'`）：半掩体目标 AC +2，四分之三掩体 AC +5；`coverAcBonus`／`coverNote` 与合法取值列表 `coverTypes` 位于 `apps/web/src/combatModifiers.ts`。
- 命中判定使用修正后的 AC，日志会写「目标处于半掩体（AC +2）」；攻击面板新增「目标掩体」下拉，默认「无」，不影响原有攻击。
- 未实现：掩体对敏捷豁免的加值、视线与遮挡的自动推断（当前由操作者判断并选择）。

## 12. 借机攻击（v1.9）

- 触发：已放置的单位在方格战场上移动，离开某个敌对单位（阵营不同、非中立、仍在场）的触及范围时，为该单位写入一条待结算提示，日志写「A 离开 B 的触及范围，B 可以借机攻击。」
- `actorReach(actor)` 取攻击来源中最远的近战距离（至少 5 尺），因此戟（10 尺）等单位在 10 尺内仍被威胁；只比较离开前与移动后两点的距离，不再判断路径经过的格子。
- `opportunityAttack(battle, reactorId, overrides?)`：默认用该单位第一个攻击来源，也可覆盖；固定消耗反应（已用过会报「该单位本回合已经使用过反应。」），并跳过方格距离校验——借机攻击按触发瞬间的触及关系结算。结算后移除提示。
- `declineOpportunity(battle, reactorId)`：放弃提示并记录日志。结束回合时会清空所有未结算提示。
- `AttackOptions.ignoreDistanceCheck` 为内部开关，普通攻击不使用。
- 存档：`CombatState.pendingOpportunity?: { reactorId: string; targetId: string }[]`（最多 8 条），`isCombatState` 校验，旧存档无需迁移，仍为 `version: 1`。
- 界面：回合面板新增「借机攻击」卡片，显示 `反应者 → 触发者`，⚔ 结算、× 放弃。
- 未实现：移动路径逐格判定（走出一格又走回不触发）、借机攻击对速度的限制（触发后无法继续移动的变体规则）。

## 13. 困难地形（v1.10）

- `toggleDifficultCell(battle, x, y)`：在方格战场上切换某格的困难地形标记；需要已启用方格，坐标须为合法整数且在范围内，否则报错。每次切换都会写日志（「(x, y) 标为困难地形。」／「取消 (x, y) 的困难地形。」）。
- 移动结算：进入困难地形格时，本次移动消耗翻倍（`格数 × cellFt × 2`），日志注明「困难地形使消耗翻倍」；不在困难地形的移动消耗不变。
- 清理：关闭方格会清空全部困难地形标记；缩小方格时超出范围的标记自动丢弃。
- 存档：`Battle.difficult?: { x: number; y: number }[]`（最多 400 格），`isBattle` 校验，旧存档无需迁移，仍为 `version: 1`。
- 界面：方格面板新增「标记困难地形」模式按钮，开启后点击格子即可切换；困难格显示斜纹底色与虚线边框。
- 未实现：移动路径中途经过的困难地形（当前只按起点到终点的直线距离近似）、困难地形对跳跃／飞行的影响、其他地形效果（冰面、荆棘等）。

## 14. 墙体与视线（v1.11）

- `toggleWallCell(battle, x, y)`：切换某格的墙体标记；需要已启用方格，坐标须合法，格子上已有单位时拒绝（「该格已有单位：X，无法设为墙体。」）。日志写「(x, y) 设为墙体。」／「拆除 (x, y) 的墙体。」。
- **移动**：不能移动到墙体格（「不能移动到墙体格子。」）；已放置单位沿直线穿过墙体时拒绝（「移动路径被墙体阻挡。」）。路径取起点到终点之间的格子（Chebyshev 逐格取整，不含端点），可绕行。
- **视线**：`hasLineOfSight(battle, from, to)` 用同样的逐格取整判断两点之间是否被墙体阻挡；双方都已放置时，远程攻击若视线被阻挡会报「视线被墙体阻挡，无法进行远程攻击。」。近战与借机攻击不受影响。
- 清理：关闭方格会清空全部墙体；缩小方格时超出范围的墙体自动丢弃。
- 存档：`Battle.walls?: { x: number; y: number }[]`（最多 400 格），`isBattle` 校验，旧存档无需迁移，仍为 `version: 1`。
- 界面：方格面板新增「标记墙体」模式（与「移动模式」「标记困难地形」并列），墙体格显示深灰斜纹。
- 未实现：墙体的高度与遮挡（矮墙可越、可越射击）、斜向墙角的最优判定、视线对掩体等级的自动换算。

## 15. 撤离（v1.12）

- `disengage(battle, actorId)`：消耗一个动作，标记本回合已撤离；此后本回合内的移动不再写入借机攻击提示（`threatPrompts` 直接跳过）。日志写「X 使用撤离，本回合移动不会引发借机攻击。」。
- 限制：只有当前行动者可以撤离（否则报「只有当前回合的单位可以撤离。」）；倒地／失能等状态由 `actionBlocker` 统一拦截；动作已用过报「该单位本回合已经使用过动作。」。
- 重置：轮到该单位的新回合时 `disengaged` 与动作等资源一起复位。
- 存档：`CombatantState.disengaged?: boolean`，`isCombatant` 校验，旧存档无需迁移，仍为 `version: 1`。
- 界面：当前行动者面板的资源条下方新增「撤离」按钮，已撤离时显示「本回合已撤离」并禁用。
- 未实现：撤离后仍可攻击的变体（如游荡者的灵巧动作）、撤离与其他移动方式的联动（跳跃、传送）。

## 16. 战术建议（v1.13）

- 模块：`apps/web/src/combatAi.ts`（不依赖 React，可在测试中直接调用）。
- `suggestAttacks(battle, actorId, limit = 3)`：对当前行动者的每个「敌人 × 攻击来源」组合给出建议，字段为 `{ targetId, targetName, source, distanceFt, inRange, score, reason }`。
- 评分：能立即攻击 +1000，目标剩余生命比例越低加分越高（最多 +100），平均伤害（骰子期望值）每点 +2，距离每 5 尺 −1，结果保留一位小数后降序排列。
- 判定：未启用方格时视为在范围内；近战按「距离 ≤ 来源触及」；远程要求视线未被墙体阻挡且距离 ≤ 600 尺。
- `reason` 用中文说明可执行性与差距，例如「距离 30 尺，在「短弓」的射程内，平均 7 点伤害。」「距离 30 尺，需要再靠近 25 尺才能触及。」「距离 30 尺，但视线被墙体阻挡。」
- `hasImmediateAttack(battle, actorId)`：存在 `inRange` 建议时为真，供界面与后续自动行动使用。
- 界面：当前行动者面板新增「战术建议」卡片，逐条显示目标、来源、理由；「填入攻击表单」按钮会把目标、来源、加值、伤害骰、类型、距离一次性同步到攻击表单（不能立即攻击的项禁用）。
- 未实现：真正的自动行动（自动选目标并结算、自动移动寻路）、多目标范围技与资源优先级的联合优化。

## 17. 自动掩体判定（v1.14）

- `coverFromWalls(battle, from, to)`：取两点连线经过的格子（不含端点）再加上两端所在格，统计与之相邻（Chebyshev ≤ 1）的墙体数量：0 → 无掩体，1 → 半掩体，2 个及以上 → 四分之三掩体。未启用方格时返回「无」。
- 攻击接入：`AttackOptions.autoCover?: boolean`。开启且未显式指定 `cover` 时，`validateAttackOptions` 会把 `coverFromWalls` 的结果写入攻击上下文，`resolveOneAttack` 用它计算 AC 与日志（`半掩体（AC +2）`、`四分之三掩体（AC +5）`）。
- 优先级：显式 `cover` > 自动判定 > 无掩体；关闭 `autoCover` 即回到无掩体。
- 界面：攻击表单新增「按墙体自动判定掩体」复选框（默认开启），与「目标掩体」下拉并存。
- 未实现：矮墙／高墙区分、斜向墙角的最优取整、多段墙体形成的连续遮蔽、掩体对敏捷豁免的影响。

## 18. 准备动作（v1.15）

- `readyAction(battle, actorId, { action, trigger })`：消耗一个动作，记录「要做什么」和「什么时候做」；动作与触发条件各不超过 120 字。日志写「X 准备「用短弓射击」，触发条件：敌人进入 30 尺。」。
- 限制：只有当前行动者可以准备（否则「只有当前回合的单位可以准备动作。」）；倒地／失能由 `actionBlocker` 拦截；动作已用或已有准备时报错。
- `triggerReadyAction(battle, actorId)`：消耗反应执行，清空准备；没有准备或反应已用时分别报「该单位没有准备好的动作。」「该单位本回合已经使用过反应。」；不在场单位不能执行。
- `cancelReadyAction(battle, actorId)`：主动放弃，动作不返还。
- 失效：轮到该单位的新回合时 `endTurn` 会清空准备并记「X 的准备动作在回合开始时失效。」（与规则书一致）。
- 存档：`CombatantState.ready?: { action, trigger }`，`isCombatant` 校验非空且长度 ≤ 120，旧存档无需迁移，仍 `version: 1`。
- 界面：当前行动者面板新增「准备动作」表单（动作 + 触发条件 + 按钮）；准备后显示 chip 与「触发（消耗反应）」「放弃」按钮，单位卡显示「准备中」标记。
- 未实现：把准备动作与具体攻击／法术动作绑定（触发后自动结算）、准备移动（准备时声明路径）。

## 19. 附带的额外伤害（v1.16）

- `AttackOptions.extraDamageExpression` 与 `extraDamageType`：主伤害之外再掷一组骰子并单独按自己的类型结算，适合猎人印记、至圣斩这类「命中后再加一段伤害」的效果。
- 结算顺序：主伤害先按目标抗性／免疫折算，额外伤害再单独调用一次 `applyDamageToActor`；两者相加写入 `AttackOutcome.damage`，额外部分单独放在 `AttackOutcome.extraDamage`。
- 重击：额外骰默认随重击翻倍（`extraDamageCritical` 省略即翻倍），置 `false` 时只掷一次，用于不随重击翻倍的效果。
- 校验：额外骰式必须能解析（`parseDice`），有骰式时必须给出合法伤害类型，否则分别报「伤害骰格式无效，请使用如 2d6+3 的写法。」与「请选择额外伤害的类型。」。
- 日志：汇总行写成「命中，造成 12 点伤害（含额外 4 点火焰伤害）」，detail 追加「额外 8 点火焰伤害（抗性）」这类说明。
- 界面：攻击表单新增「额外伤害」「额外伤害类型」「额外伤害随重击翻倍」，留空即不加附伤。

## 20. 战斗中的增援（v1.17，界面 v1.18）

- `addReinforcement(battle, card, { side, initiative?, position?, name? }, deps?)`：把一张怪物卡作为新单位插入**进行中**的战斗。动作与回合不被重置，返回 `{ battle, actorId, initiative }`。
- 先攻插入：按先攻从高到低插进 `combat.order`；插入点位于当前行动者之前时把 `turnIndex` 加一，因此当前行动者不会因为增援插队而换人。未指定 `initiative` 时掷 `d20 + 先攻加值`（含警觉等修正）。
- 初始状态与新回合一致：`actionUsed / bonusUsed / reactionUsed` 均为假、`movementUsed` 为 0、`status` 为 `active`；生命值取怪物卡的平均值。
- 位置：带 `position` 时必须已启用方格战场（否则「请先启用方格战场。」），格子必须落在范围内（「目标格子超出战场范围。」）且不能与已有单位重叠（「该格已有单位：X。」）。
- 校验：未开始战斗报「请先开始战斗再加入增援。」；名称与怪物名都为空报「请填写增援单位的名称。」；生命值非正整数报「增援单位的生命值无效。」；手工先攻越界报「先攻值须为 -20 至 60 的整数。」。
- 日志：`哥布林援军 以先攻 25 加入战斗。`
- 界面：战斗页的「增援」卡片可选择怪物卡、阵营、名称、先攻与（已启用方格时的）目标格子；留空先攻即自动掷骰。

## 21. 起身（v1.19）

- `standUp(battle, actorId, deps?)`：消耗「一半速度（向下取整）」的移动力，移除 `倒地` 状态；30 尺速度即消耗 15 尺。
- 校验：非当前行动者报「只有当前回合的单位可以起身。」；没有倒地报「该单位没有倒地。」；`status` 不是 `active`（倒地死亡）报「只有在场的单位可以起身。」；剩余移动力不足报「剩余移动力不足，起身需要 N 尺。」。
- 日志：`X 起身，消耗 15 尺移动力。`
- 注意：`倒地` 是状态列表里的标记（`conditions`），本身不拦截动作；真正拦截动作的是 `status: 'down'`。起身只清标记与移动力，不会恢复生命值，也不会自动结束死亡豁免。
- 回合结束不会自动起身；需要时手动结算。
- 界面：当前行动者处于倒地时，条件选择器旁出现「起身（消耗一半移动力）」按钮。

## 22. 持续效果的结算时机（v1.20）

- `OngoingEffect.timing`（`'start' | 'end'`，省略即 `'start'`）：持续伤害与豁免可以在**自己回合开始**或**自己回合结束**时结算。
- `endTurn` 会先用「即将结束回合的单位」结算 `timing: 'end'` 的效果，再推进到下一个单位；推进后只结算新回合单位的 `timing: 'start'` 效果。两种时机互不重复。
- 带 `saveEnds` 的效果在各自时机掷豁免，成功即移除并记「通过X豁免，结束「Y」。」；失败则继续保留。
- 校验：`timing` 不是 `start`/`end` 时报「持续效果的结算时机无效。」。
- 日志前缀区分「回合开始：」与「回合结束：」，例如 `回合结束：「灼烧」对 哥布林 造成 4 点火焰伤害，剩余 11/15。`
- 界面：持续效果表单新增「结算时机」下拉（回合开始／回合结束），chip 上标注时机。

## 23. 战果与经验（v1.21）

- 新增 `apps/web/src/encounterReward.ts`：按 2024 版挑战等级表把已击败单位换算成经验值。
- `crXp(cr)`：接受 `'1/4'`、`'1/2'`、`'5'`、`0.25` 这类写法；表覆盖 CR 0–30（10 ~ 155000），无法识别返回 0。
- `defeatedActors(battle)`：`combat.status === 'dead'` 的单位；`encounterXp(battle)` 累加它们的经验（同种怪物多只分别计算）。
- `encounterReward(battle)` → `{ xp, defeated, remaining, completed }`；`completed` 表示敌方已无存活单位（`side === '敌方'` 且未死亡）。
- `rewardSummary(battle)`：给界面与战报的一句话，例如「战斗结束：击败 2 个单位，共 100 点经验。」「已击败 1 个单位，获得 50 点经验；仍有 1 个敌方单位在场。」
- 界面：战斗页在战斗日志上方展示这行战果说明。
- 注意：经验只按「已死亡」统计，倒地未死不计；难度调整（多个怪物倍数）暂不自动计算，需要时人工折算后再入账。

## 24. 武器特性：重型（v1.22）

- `attackSources.ts` 的武器表新增 `properties`：巨剑、巨斧、戟为「重型／双手」，战锤、长棍为「重型」；`AttackSource` 同步暴露 `properties`，只有装备武器来源带值。
- `AttackOptions.weaponId`：攻击时传入选中的攻击来源 id（界面在选中「攻击来源」后自动带上）。找不到对应来源时报「攻击来源无效。」。
- 重型规则：使用者力量低于 13 时，攻击检定具有劣势（与其它优势／劣势按原有规则抵消）。日志 notes 会写「力量 8 低于重型武器要求的 13：攻击检定劣势」。
- 未传 `weaponId` 时行为不变（仍按状态、掩体、距离结算），因此旧存档与手工填写的攻击不受影响。
- 力量取值：角色用 `sheet.abilities.str`，怪物用 `template.abilities.str`，都缺省时按 10 处理。

## 25. 两用武器的双手形态（v1.23）

- 武器表新增 `versatile`：长剑 1d10、战锤 1d10、长棍 1d8、长矛 1d8；`AttackSource.versatileDamage` 同步暴露给界面。

## 68. 长休恢复（v1.73–v1.85）

- v1.85 起长休还按规则补全：存活单位恢复**全部生命值**、清空临时生命、倒地者复活并移除「倒地」、死亡豁免归零、力竭等级减 1（减到 0 即删除）、清除 stable／delayed 标记；阵亡单位不受影响。
## 69. 力竭（v1.74）

## 75. 长武器大师：柄端攻击（v1.80）

## 76. 哨兵（v1.81）

- `setSentinel(battle, actorId, enabled, deps?)`：开启后该单位获得两条哨兵效果（开关本身不消耗动作）。
- **长武器减速**：被该单位的长武器（特性「长武器」，或名称含戟／长棍／长矛）命中且仍存活的敌人，本回合剩余移动力清零（`movementUsed` 直接推到速度上限，速度仍按困难地形／力竭等修正计算）。
- **代为反击**：敌对单位在哨兵 5 尺内攻击**其他人**（包括其他角色与召唤物）时，会在待结算列表里生成一条「哨兵盯住」的借机提示，哨兵可花反应用 `opportunityAttack` 出刀；攻击哨兵本人、反应已用、或攻击本身来自反应时不触发。


## 77. 稳定伤势（v1.82）

- `stabilize(battle, actorId, targetId, deps?)`：用动作对 5 尺内倒地的同伴做 DC 10 医药检定（感知），成功给目标置 `stable` 标记并记日志「…稳定了…的伤势（DC 10）」。
- 已稳定的单位：`rollDeathSave` 直接拒绝（「该单位已经稳定，不需要掷死亡豁免。」），开启「回合开始自动掷死亡豁免」时也会跳过它。
- 稳定状态在再次受到伤害时解除，并按倒地受击规则照常追加一次死亡豁免失败；被治疗站起时也会一并清除。
- 界面：回合面板的「治疗」区块新增「稳定伤势（动作，医药 DC 10）」按钮。


## 78. 延迟行动（v1.83）

- `delayTurn(battle, actorId, deps?)`：当前行动者把自己的回合挪到本轮最后，`turnIndex` 顺移给下一位行动者；不消耗动作，也不清空已用资源。
- 该单位获得 `delayed` 标记（界面可显示），下次轮到它时在 `resetTurnResources` 里自动清除。
- 限制：只有当前回合的单位可以延迟；必须是本轮倒数第二位之前（否则「已经是本轮的最后一个行动者」）；只有一名行动者时无法延迟。


## 79. 飞行（v1.84）

- `setFlying(battle, actorId, enabled, deps?)`：起飞／落地开关，不消耗动作；死亡单位不能起飞。
- 飞行期间：移动消耗不再因困难地形、水下、攀爬、冰面、岩浆翻倍（日志改记「飞行忽略地形消耗」），进入危险地形与岩浆都不结算伤害，冰面也不会滑倒。
- 仍照常触发借机攻击（离开触及范围时）、仍受速度上限与力竭等修正约束；落在地形危险格上时，落地不会补算伤害（下次移动或回合开始才结算）。


## 80. 自动撤退（v1.86）

## 88. 连续攻击分散到多个目标（v1.94）

## 139. 中毒对属性检定的劣势（v2.43）

- 5e 规则里「中毒」同时使攻击检定与属性检定带劣势。v2.42 只做了攻击检定，本版补齐属性检定。
- 新增内部函数 `poisonedCheckRoll(battle, actorId, bonus, random)`：中毒者掷两次 d20 取低值，返回 `{ natural, total, notes }`，`notes` 形如 `中毒：属性检定劣势（19/3 取 3）`。
- 接入两处对抗检定：
  - `grappleContest`（擒抱与推撞共用）：攻击方与目标双方都走 `poisonedCheckRoll`，日志在原来的「力量（运动）对抗…」之后追加一条「… 受中毒影响，中毒：属性检定劣势（…）。」
  - `escapeGrapple`：力量（运动）或敏捷（体操）检定同样带劣势，劣势说明直接拼进挣脱日志的括号里。
- 未中毒时仍只掷一次骰子，随机序列消耗数量不变（既有测试与自动行动不受影响）。

## 181. 投降者挨打即重新投入战斗（v2.85）

投降不是免疫。投降单位一旦受到实际伤害，就会立刻恢复战斗状态：

- `applyDamageToActor` 在算出实际伤害后判断：`if (battle && adjusted > 0 && state.surrendered === true)` → 删除 `surrendered`，写日志「… 遭到攻击，重新投入战斗。」。
- 「实际伤害大于 0」这一条很关键：完全被免疫或抗性削减到 0 点、以及治疗，都不会取消投降。
- 恢复后 `nextTurnIndex` 会重新把它算进回合循环，经验结算也不再提前把它当成「已击败」。
- 处决不受影响：`executeCaptive` 直接置 0 生命与阵亡状态，不走伤害通道，所以「处决投降者」仍然一次完成。

## 183. 不能行动的单位不再排队借机攻击（v2.87）

以前只要敌对单位还带着 `status === 'active'`，离开它的触及范围就会排队一条借机攻击提示——即使它处于麻痹、失能、昏迷、石化，或者已经撤离、投降、倒地。结果战报里出现「可以借机攻击」的提示，玩家点下去却只会收到「处于麻痹状态，无法进行动作、附赠动作或反应。」

- `apps/web/src/combat.ts` 新增内部判定 `canReactNow(actor)`：在场、未撤离、未投降、且 `actionBlocker(actor) === null`。

## 184. 准备动作也要看能不能行动（v2.88）

上一版让借机攻击只在「真的能反应」时才排队，但`triggerReadyAction`/`resolveReadyPrompt`这条路径漏了同样的校验：一个已经麻痹的单位仍然能把准备好的动作兑现成一次反应，并且会把待确认的提示消费掉。

- `apps/web/src/combat.ts` 的 `triggerReadyAction`：在「只有在场的单位可以执行准备好的动作。」之后补 `if (!canReactNow(actor)) throw new Error('该单位现在无法行动，不能执行准备好的动作。');`
- `resolveReadyPrompt`：在取到提示后、移除提示前做同一判断，因此**提示不会被白白消费**，准备状态也保留在单位身上。
- 与 `readyPrompts` 的生成过滤一致：提示本来就不再给麻痹/失能/倒地/撤离/投降的单位排队，这里是执行侧的兜底。

## 232. 驱散魔法覆盖新法术（v3.10）

## 235. 沉睡术改为专注法术（v3.11）

沉睡术此前是个「一锤子买卖」：掷一次 5d8 生命值池，把放得倒的人放倒，随后施法者可以去放别的法术、甚至躺下，睡着的人一直不醒。2024 规则里睡眠是**专注法术**，打断专注就该把睡着的人全叫醒。

- `apps/web/src/battle.ts`：`CombatantState` 加 `sleepingBy?: string`，记录是谁让人睡着的（校验 1–64）。
- `apps/web/src/combat.ts` 的 `castSleep`：已有专注时抛「施法者已经在维持其他专注。」；施放成功后登记 `concentration = { spell: '沉睡术' }`；每个睡着的目标写 `sleepingBy`。
- `clearFocusBuffs` 补沉睡块：按 `sleepingBy === casterId` 找到睡着的人，清 `sleeping`／`sleepingBy` 与「失能」「倒地」，写「… 从沉睡中醒来」。因此结束专注、死亡、撤离、投降、移除单位五条路径都会唤醒。
- 受伤唤醒（`applyDamageToActor`）与手动 `wakeUp` 保持原样；两者都不结束专注，施法者可以继续维持或主动结束。

## 238. 长休清除残留条件（v3.12）

长休会删掉 `paralyzed`、`blinded`、`deafened`、`sleeping`、`entangled` 这些字段，却没删它们留下的**条件标记**。结果是：被定身术麻痹过的单位睡了一夜，`麻痹` 还在 `conditions` 里，`actionBlocker` 继续判定它不能行动——一觉醒来比睡前更糟，而且没有任何轮数会把它清掉。

- `apps/web/src/combat.ts` 的 `takeLongRest`：在清理字段之后统一过滤一次条件，移除 `失能`、`束缚`、`麻痹`、`目盲`、`耳聋`、`恐慌`、`魅惑`、`倒地`。
- 倒地也一并恢复：睡满八小时后没理由还趴着；此前只有「长休前处于 down」的分支才会清倒地，被沉睡术放倒但仍是 active 的单位会一直保持倒地。
- 顺带补上 `sleepingBy` 的清除，避免醒来后残留施法者引用。

`tests/combatRestConditions.test.cjs`：5 项，覆盖定身、致盲、恐惧、纠缠、沉睡五种来源的条件在长休后全部消失。

## 241. 变形术到期解除失能（v3.13）

`resetTurnResources` 用一个循环统一递减加速术、隐形术、缓慢术、变形术、树肤术的轮数。递减到 0 时它删掉字段、写「…结束了」，但变形术还额外挂着一个 `失能` 条件——**到期时没人摘**。于是变形的小兽十轮后变回原样，却永远不能行动，跟 v3.12 长休那条是同一类问题。

- `apps/web/src/combat.ts` 的 `resetTurnResources`：循环里删字段之后判断 `if (key === 'polymorphed')`，把 `失能` 从 `conditions` 过滤掉。
- 主动结束专注（`clearFocusBuffs`）与驱散魔法两条路径此前已经会清条件，现在三条到期路径口径一致。

`tests/combatPolymorphExpire.test.cjs`：4 项，覆盖到期摘标记、未到期保留、到期后 `actionBlocker` 返回 null（可行动）、到期写日志。

## 253. 施法不再原地改写传入档案（v3.17）

`castSpell` 原本先拿 `battle` 本体校验，然后用 `const tracked = caster.combat?.spellSlots` 直接扣法术位——`caster` 来自**传入的那份**战斗对象，于是扣位这一步在调用方眼皮底下改写了原档案：

- 调用前若已 `structuredClone` 做撤销快照，快照里的法术位会跟着一起变，撤销后法术位仍是扣过的；
- React 里同一个对象被就地修改，比较引用发现不了变化，界面可能不刷新或显示旧值。

改为进入函数后立刻 `let next = structuredClone(battle);`，后续校验、扣位、写日志全部作用在副本上；只有 `next` 返回给调用方。

- 判定走统一的 `applyDamageToActor`，因此抗性／易伤的先后顺序保持「角色防御 × 地形修正」，统计里的承伤与伤害构成记录的都是修正后的数值。

`tests/combatWaterConduct.test.cjs`：5 项，覆盖闪电翻倍、雷鸣翻倍、陆地闪电不变、水下火焰抗性与导电并存、挥砍不受影响。

## 280. 自动推进的停止原因（v3.26）

「自动推进敌方」连续跑同一阵营的回合，遇到换边或无法行动时就静默 `break`。界面上看不出是打完了、还是轮到别人了。

- `turns` 的语义完全不变（只装真正执行过的回合），既有调用方与断言无需改动；`main.tsx` 在停止原因不是「战斗结束」时把提示打到控制台。
- 达到 `maxTurns` 上限也会给出 `limit` 原因，方便区分「打完了」与「跑满上限」。
- 停止原因（`finished` 除外）也会追加进战报，导出的 Markdown 里能看到「轮到谁了、为什么没继续」。

## 281. 自动行动绕开会让人吃亏的格子（v3.27）
