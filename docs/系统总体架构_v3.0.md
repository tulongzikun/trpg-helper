# TRPG Helper — 系统总体架构与设计索引 v3.0

> 版本：v3.0（2026-11-10）
> 系统范围：**独立车卡系统 + 单机多单位战斗系统 + 发布快照导入协议 + 统一前端设计**
> 规则基线：D&D 2024 / SRD 5.2.1；未来通过独立规则策略适配 2014 / SRD 5.1
> 交付性质：架构和交互设计文档，不表示当前仓库已具备可运行代码

## 2. 完整产品结构

~~~text
TRPG Helper（单个浏览器 Web App；无需联网对战）
┌────────────────────────────────────────────────────┐
│ 顶部导航：角色库 | 新建角色 | 战斗 | 怪物库 | 规则包    │
├──────────────────────────┬─────────────────────────┤
│ 车卡独立模块              │ 战斗独立模块              │
│ Character Builder        │ Combat Simulator        │
│ • 从零创建/编辑角色       │ • 多 PC、怪物、召唤物      │
│ • 属性、职业、背景与物种   │ • 先攻和回合/反应          │
│ • 法术、装备、熟练、特性   │ • 行动、附赠动作、额外攻击  │
│ • 校验、保存、升级        │ • AoE 覆盖全部受影响单位   │
│ • 发布角色 Snapshot N    │ • 伤害、专注、濒死、胜负   │
└────────────┬─────────────┴──────────────▲──────────┘
             │                            │
             └── CharacterSnapshot v1 ────┘
                       │     Battle Import Adapter
             ┌─────────▼───────────────┐
             │ Shared Rules + Contract │
             │ Version / Hash / Schema │
             └─────────────────────────┘
~~~

**边界**：车卡与战斗 UI 分开，角色库可离线完整使用。战斗只通过已发布快照读取角色构筑，不直接修改车卡中的数据和历史修订。每场战斗的 HP、法术位剩余、召唤物、专注、轮次、位置都属于独立 BattleState。

## 3. 角色创建到进入战斗的用户路径

~~~text
打开“角色库”
  → “新建角色”
  → 按规则完成向导：职业 / 起源 / 属性 / 技能 / 特性 / 装备 / 法术
  → 实时预览六维、HP、AC、法术能力及职业特性
  → 保存草稿 → 校验 → 发布不可变快照 Rev N
  → 点击“导入战斗”
  → 选择已有或新建 Battle
  → 选择阵营、初始 HP/资源、位置
  → 规则兼容与能力解析检查
  → 创建新的 BattleActor
  → 与任意数量 PC、怪物、召唤物同场战斗
~~~

草稿不允许直接导入。不同 Battle 可以使用同一角色的独立实例；角色升级只产生新修订，不修改已在进行中的对局。

## 4. 战斗交互路径

~~~text
创建战斗（2+ 阵营，PC / 怪物）
  → 导入已发布 PC + 手工添加怪物
  → 初始化先攻 / 回合
  → 统一“选择操作”弹窗：合法单位 → 能力/动作 → 目标/区域 → 确认
  → 若有反应：暂停 → 响应弹窗 → 恢复结算
  → 自动骰子/命中/豁免/伤害/消耗/专注/死亡
  → 更新全部 Actor 与召唤物、区域、日志
  → 下一个合法行动 / 结束回合 / 判断阵营胜负
~~~

- 附赠动作每单位自己的回合**最多 1 次**，职业特性或动作如潮不能重置。
- Extra Attack 仅增加某次 Attack Action 内攻击次数；战士 5 级、额外动作等由规则版本严格判定。
- 怪物 Multiattack 是其属性块定义的一个多段动作，不等于战士 Extra Attack。
- 召唤物依据其来源拥有独立行动、共享回合或主人指挥要求，**必须列入 AoE 可影响对象**。
- AoE 地图模式由几何和规则自动求受影响者；无地图模式显示显式的人工范围申报提示；友军及召唤物不应无故被自动剔除。

## 5. 前端原则

- 车卡使用「步骤导航 + 选择与规则说明 + 实时预览」；角色页「概览/能力/特性/法术/装备/背景/修订」。
- 战斗使用「单位先攻侧栏 + 地图/目标区 + 当前角色与日志侧栏」；每次实际行动经操作弹窗，反应为中断专用弹窗。
- 主色为深灰和少量金色，代表奇幻题材；界面布局、组件、素材均原创，不复制 TRPGCard。
- 由领域层统一生成合法选项、禁用原因和 AoE 目标列表；React 仅渲染与提交命令，不独立计算 D&D 规则。
- 支持桌面优先 + 平板/手机响应式、键盘/焦点、无障碍、草稿自动保存和战斗恢复。
- 具体 token、线框图、组件输入输出、异常态、端到端验收见《前端交互与视觉设计 v1.0》。

## 6. 模块与依赖约束

~~~text
packages/rules              版本化规则 JSON/DSL 与计算策略
packages/contracts          CharacterSnapshot v1 和校验 schema
packages/character-core     Builder Draft/Choice/Validation/Sheet/Publish
packages/battle-import      Snapshot → BattleActor（唯一桥梁）
packages/combat-core        Turn/Actions/Effects/Events/Summons/AoE/Death
apps/web/src/features/characters  车卡页面与独立状态
apps/web/src/features/battles     战斗页面与独立状态
apps/web/src/components/ui       共享无业务规则的原子 UI
~~~

**不得出现** `character-core → combat-core` 依赖；`combat-core` 不直接加载 `CharacterDraft`；可共享 `rules`、`contracts` 和纯展示组件；角色库和战斗本地存储独立。

## 7. 技术栈与交付次序（建议）

- UI：React + TypeScript + Vite；Tailwind/CSS Variables；Dialog/Sheet/Select 等使用可访问的 Headless 组件方案。
- 规则：纯 TS 函数 + RulePack（来源/版本/hash）；Zod/JSON Schema 作为数据边界验证。
- 本地：IndexedDB（Dexie 可选）；战斗事件与快照原子保存；无需 WebSocket/服务端。
- 测试：领域单测、规则基线与属性测试、关键交互组件测试、Playwright E2E、截图回归。

| 顺序 | 里程碑 | 完成判据 |
|---|---|---|
| 1 | Rules / Contracts + UI 组件库 | 规则/快照结构可验证，基础组件支持键盘 |
| 2 | 车卡引擎 + 向导 | 独立创建并发布有效 1 级 PC，刷新可恢复 |
| 3 | 角色库 / 升级 / 快照导入 | 5 级战士拥有正确职业特性，多个 Battle 实例隔离 |
| 4 | 战斗行动、反应和附赠动作 | Extra Attack + Action Surge 不突破 Bonus Action 限制 |
| 5 | 召唤、AoE、状态与死伤 | 2 PC + 3 怪物 + 2 召唤物的完整对战 |
| 6 | 前端完善、规则追溯、回放 | 375/768/1280/1600px，键盘、失败恢复、回放验收 |

## 8. 法规/版权、外部平台集成与真实性说明

TRPGCard 只作为公开参考案例，不能假定其提供稳定开放 API、源码或可复制的受许可美术素材。若将来需要导入 TRPGCard 角色，必须通过用户有权限的合法导出或明确可用的接口；外部格式先映射至本项目草稿并完成校验，再由本项目发布角色快照，最后导入战斗。规则数据以 SRD 开放许可为基础，遵守对应归属和授权要求，不将受限的非 SRD 内容视为可分发资产。

---
**整体验收**：同一离线浏览器应用内，独立完成车卡、校验、升级与发布，通过不可变快照导入多单位战斗；界面能完整展示职业行动、附赠动作、反应、召唤物和 AoE 对象的合法性与结算过程；全程不让战斗运行时资源污染原车卡。
